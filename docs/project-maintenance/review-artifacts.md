# Study and discussion artifacts

Author direction, 23 October 2026: Markdown used to study, discuss or compare
analyses belongs with the corresponding HTML on JOAQUIM. File format does not
decide repository ownership. Numbered implementation plans remain in `Plans/`.

| Material | Canonical home |
|---|---|
| Explanatory study manuscript, model comparisons, questions, discussion checkpoints and provisional preferences | JOAQUIM review workspace, alongside its HTML |
| Published study HTML, source snapshots/assets, retained revisions and exported review notes | The same external topic workspace |
| Numbered future implementation work and progress index | `Plans/` |
| Repository instructions, skills, storage rules and operational documentation | Their existing repository or personal-skill home |
| Approved scientific definitions, explicit decisions, scoped selection/state, frozen records and supported code/tests | Existing authoritative repository homes |
| Compact discovery, provenance and exact-recovery metadata | Existing repository catalogue and record formats |

Classify the content, not the extension or folder name. An essay comparing
unselected learner methods is study material even if currently filed under
`docs/paper/methods/`. A concise approved outcome definition remains repository
documentation. Split mixed documents without changing accepted definitions;
keep a short pointer to the full external discussion.

For new work, use a scope-based workspace under:

```text
/Volumes/JOAQUIM/ClassicalConditioning Outputs/studies/
  figure-02/panel-g/
  figure-02/panel-h/
  figure-02/panel-i/
  figure-03/
  figure-04/
```

Within a topic, keep an editable explanatory source (normally `study.md`), its
`study.html`, existing project-native evidence/provenance, required sources and
retained revisions. Add conversation files or exported notes only when needed.
Keep the existing single-file HTML or relative-asset contract; a Markdown source
does not replace the standalone reading artifact. Canonical manuscript edits
belong on the SSD, not in two independent repository/SSD working copies.

The existing [review library](../paper/figures/review-library.md) remains the
entry point. Its compact catalogue locates exact sources and reading artifacts;
it does not choose an analysis or replace scoped presentation state. Its
generated `review-library/<identity>/reading/` files are dated convenience
snapshots, not canonical manuscripts to edit.

The personal `analysis-review-guide` skill owns reusable teaching, comparison,
notebook and revision behavior. This policy owns this repository's storage
choice. Keep the personal skill outside the repository; no additional agent
or second project skill is required for this division of work.

Open questions, recommendations and provisional choices stay in the external
study. After an explicit author decision, record the concise agreed choice,
scope, evidence identity and limitations in the existing repository decision
or selection workflow. Study notes do not approve science or trigger a freeze.

Existing bundles retain their paths until the reader, relative-link, source-hash
and notebook-origin dependencies are reconciled under the
[migration plan](../../Plans/12_STUDY_ARTIFACT_STORAGE.md). Preserve exact frozen
and hash-bound originals. Verify SSD copies and recovery before removing any
redundant working source; do not weaken preservation checks or substitute an
older artifact. If the SSD is unavailable, record pending work and continue
independent code or planning work without creating a new canonical study copy
in Git.
