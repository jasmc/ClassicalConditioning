# Script lifecycle

Keep supported tools in `scripts/`, their shared implementation in `src/` and
tests in `tests/`. Keep exact frozen reproduction snapshots under their scoped
frozen records. Superseded candidate code belongs on verified external storage
after disposition; retention in `scripts/` does not authorize new scientific use.

The [tool catalogue](../../scripts/README.md) links every retained script. The
[17 October inventory](../../records/repository-history/2026-10-17-organization-reconciliation/script-inventory.json)
is the initial dated inventory. The
[23 October assessment](../../records/repository-history/2026-10-23-script-lifecycle/assessment.json)
completes its 14 pending classifications and records decisions for the five
historical candidates plus the later download-repair helper. Both are dated
evidence, not progress boards. The initial status names below describe the
17 October inventory; they do not leave those 14 files unclassified today.

| Recorded status | Meaning |
|---|---|
| `supported-or-dependency` | Current docs, tests, implementation or another retained tool references the file; preserve its dependency closure. |
| `catalogued-reproduction-or-audit` | Documented reproduction/audit entry with no additional active text consumer found. |
| `historical-candidate-retained` | Inspected dated recipe with temporary-ticket assumptions and/or retired styling; retain for provenance pending author disposition. |
| `retained-pending-classification` | No active reference was found; absence of a text match is not proof that removal is safe. |

Before moving any candidate, resolve imports, current state/evidence bindings,
frozen dependencies and exact recovery needs. Prepare a concrete scoped
disposition inventory. Execute archival or deletion only under the applicable
author authorization, using [verified storage procedures](storage.md). Preserve
pending originals and dependency closure until then. The organization
reconciliation itself archives and deletes no scripts.

## Implemented audit dispositions

Author direction to implement needed audit findings supersedes the earlier
proposal-only retention status for audited completed recipes. The
[implementation record](../../records/repository-archive/script-organization-20261024/README.md)
records exact source recovery, verified retirements, helper extraction and the
current scoped command paths. Earlier inventories/assessments remain immutable
historical evidence. They do not override the current catalogue or silently
approve replaying an archived freeze/publication driver.

Commands are now grouped by role and figure/panel scope, using importable Python
namespace names with underscores. Seven standing compatibility facades preserve
normal entry points and the immutable element-specification link. The catalogue
checker walks the full command tree. Guarded command snapshots include their
local implementation dependency closure so extracted helpers remain hash-bound.

## New commands and safe successors

Place new commands under their maintained operation/figure/panel scope. Keep
root facades only for explicit compatibility contracts. Document the command's
lifecycle role, inputs, outputs and modifying/publication modes in its catalogue
entry or operating guide. Reusable helpers belong in src; do not reuse a driver
by overriding its globals. Accept explicit candidate/evidence locations rather
than a personal temporary workspace. Trace callers, source bindings and recovery
before a move or retirement; preserve scientific definitions and guards.

A catalogue entry establishes discoverability, not scientific approval or safe
replay. Distinguish maintained operations, reproduction/audit tools and dated
transaction drivers. Keep historical source versions and their dependency
closure recoverable even when the supported successor has a clearer location.
Compatibility facades and exact source-bound originals are explicit exceptions
to normal scoped placement, not new templates for root commands.

The later trace commands are routed to scoped successors under Figure 1,
Figure 2 and trace workflows. Retained old paths remain compatibility entry
points or explicitly marked historical sources. Other root commands require
individual assessment before relocation; no root-file count certifies cleanup.

New candidate tools capture inputs before consuming them and retain those
identities through publication. Extend a `Snapshot` with `bind_hashes` or
`include`: conflicting earlier bindings must fail rather than be overwritten
by a later hash capture. Bind the exact browser-evidence file as well as the
candidate artifact; a fresh measurement cannot be inferred from a filename.
